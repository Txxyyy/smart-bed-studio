# 手机渲染与功耗控制

正式入口和 `?embed=1` 使用同一套性能策略。旧 `?studio=1` 是桌面设计工作台，未增加手机帧率/生命周期策略；共用几何缓存优化仍生效。

## 默认行为

`createMattressViewer(container)` 默认 `performanceMode: 'auto'`，所有设备均使用 native：保持优化前的画质，动画直接跟随屏幕 requestAnimationFrame，不设30/60帧限制。不会因触屏自动降画质。eco/balanced仅保留为App明确选择的可选档位，不默认启用。

| 档位 | 帧率上限 | 像素比上限 | 实时阴影 | 各向异性上限 |
| --- | ---: | ---: | --- | ---: |
| native / auto | 跟随屏幕 | 1.35 | 1024 | 16 |
| eco | 30 | 1 | 关闭 | 2 |
| balanced | 30 | 1.35 | 512 | 4 |
| high | 60 | 1.75 | 1024 | 8 |

实际像素比不超过设备像素比。构造参数 pixelRatio 可进一步降低上限，不会突破档位上限。省电档保留气囊数量、材质纹理、按摩隆起、扫描与叠加光效；降低像素密度和纹理斜视采样精度，关闭动态投影。默认WebGL使用default电源提示，与优化前一致，不强制低功耗GPU。

## App 接口

```js
const viewer = createMattressViewer(container, {performanceMode: 'auto'});
await viewer.setModel('T12');
viewer.setPerformanceMode('auto'); // native / auto保留原画质；eco / balanced / high为显式选择
viewer.setVisible(false); // App 页面离开、原生界面遮挡、WebView进入后台
viewer.setVisible(true);  // 页面回来：继续原有左右动画，不重置设备状态
const stats = viewer.getPerformanceStats();
```

浏览器标签页隐藏、模型容器离开视口或尺寸变为0时自动停绘；App 原生界面是否遮住 WebView 不一定产生浏览器事件，需调用 setVisible。可见性恢复时冻结期间的时间不计入扫描/镜头/按摩进度，不集中补绘后台帧。隐藏期间仍可接收设备状态，回来后趋向最新值。手动 suspend/resume 的原有重同步语义保留。

静止且无动态效果时不再调度帧；默认动画直接用requestAnimationFrame，不经过定时器限帧，60/90/120Hz刷新均不主动跳帧。实际帧率取决于设备负载；maxFps=null表示跟随屏幕。可选eco/balanced仍采用30帧节流。setVisible 与性能接口均已加入 JSON 分发白名单。

stats 包括实际档位、像素比、帧率上限、阴影开关、visible、累计renderCount、最近一帧CPU提交时间lastFrameMs、drawCalls、triangles和Three.js资源计数。lastFrameMs不含GPU完成时间，资源计数不是显存字节数，均不能直接表示手机温升。

## 减少无效工作

- 姿态不变时复用曲线采样；网格只在相关压力、按摩或姿态变化时重算，包边与Logo跟随床面版本。
- 隐藏侧气囊跳过变形，重新显示时按最新状态更新；全息光纹时间变化只更新必要的uniform和流动粒子。
- 永久隐藏的按摩囊体、底片不再逐帧更新矩阵或顶点。
- 按摩光圈与波纹的固定空间权重只计算一次；每帧重用权重与当前隆起系数相乘。网格分辨率、覆盖范围、颜色、强度和轨迹保持原值，所有顶点通过原公式等价验证。
- 阴影按床体/可见结构变化刷新，单独镜头移动不重绘阴影贴图。

## 验证边界

桌面浏览器中的390×650画布可用于比较同场景计算成本和检查停绘，不代表手机GPU、WebView兼容性或温升验收。交付到App前，需在目标Android/iPhone实机连续运行双侧调节＋加热＋按摩至少15分钟，记录帧率、CPU/GPU、温度及电量，并验证锁屏/切后台/返回、反复切型号和页面销毁。无实测数据时不承诺不发热。

## 前一版eco桌面实测（历史，非当前默认策略）

同一浏览器、390×650画布、pixelRatio=1，T12双侧支撑透视＋腰部光效＋左腰加热＋双侧按摩；预热2秒、采样5秒。优化前为旧默认渲染，优化后为eco，故同时包含几何缓存与关闭阴影的收益。

| 指标 | 优化前 | 优化后eco |
| --- | ---: | ---: |
| 每帧CPU提交均值 | 30.04ms | 18.04ms |
| 每帧CPU提交P95 | 32.50ms | 18.70ms |
| 每帧draw calls | 417 | 277 |
| 每帧三角形提交 | 497168 | 299209 |
| 约5秒提交帧数 | 166 | 131 |

单帧CPU提交时间减少约40%，绘制调用减少约34%；降低帧率上限还减少单位时间工作量。本次不是GPU计时，也不是相同画质配置比较；不能推导同等比例的温降或续航提升。复测入口为本地临时 `work/performance-check.html`，`?before=1` 使用修改前源码快照。

## 保持原画质的修正与对比（2026-09-21）

根据用户要求，撤回默认30fps、降阴影/纹理采样和强制low-power的策略。默认auto改为native，使用原有DPR≤1.35、1024阴影、16倍各向异性、抗锯齿及default GPU偏好；跟随屏幕RAF。省电档仅为显式可选项。

增加按摩表面空间权重缓存：光圈和波纹位置固定，其影响范围权重不随时间变化。预计算权重，每帧只更新各组隆起系数；保持全部顶点、颜色、强度和周期。新增测试逐点对照原函数（误差<1e-14），并核对平躺/65°背部+35°腿部所有可见效果顶点（误差<1e-6）。

原画质同场景5秒桌面采样（390×650、DPR=1.35、T12双侧支撑透视+左腰加热+双侧按摩）：旧版CPU均值28.90ms/P95 30.10ms，本版10.76ms/P95 11.40ms，均值减少约63%；draw calls 417→414，仅省掉关闭的热区绘制。5秒提交帧172→459，是本桌面浏览器提交计数，不代表手机帧率或屏幕实际呈现帧率。不能从单帧下降比例推导整体功耗/温降；仍需实机验证。

## Flutter 原生兼容展示（2026-09-22）

`RenderPolicy` 选择展示后端；`PerformanceMode` 仍管理 3D 画质。启用 auto 不更改 native 的 DPR、阴影、纹理采样或 RAF 策略，也不以一次慢帧自动降画质。WebView 初始化、桥接或上下文恢复失败时，可使用 Flutter 图片＋区域绘制；显式 twoD/staticImage 不创建 WebView。

二维沿用固定底图，复用区域几何，动态时由 Flutter 帧回调更新光效。隐藏、后台、离线和暂停停止动画；静态模式仅在状态/布局变化时重绘。App 必须提供真实 visible。自动尝试 3D 时短暂存在候选后端，完成或失败后释放无用实例；二维模式不应保留失败 WebView 的持续渲染。

默认 6 秒初始化尝试和 2 秒上下文恢复预算只计算可绘制时间，参数可配置，不能当成所有电视的性能保证。对比检查应记录启动时间、峰值内存、长时间运行、隐藏停绘和恢复状态；历史 3D 桌面数据不能证明二维电视温升或全部 GPU 驱动兼容。具体模式策略见 [RENDER_FALLBACK.md](RENDER_FALLBACK.md)，真实结果继续记录在验证文档。
