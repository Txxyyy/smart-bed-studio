# V.19 页面交互与并行调节实现方案

状态：待实施方案。基于 2026-09-09 的 V.18 源码核对；本文件不代表功能已经实现或测试通过。

本轮目标是在现有型号页面增加左右自适应调节、独立加热、电动床姿态/模式/速度和重置控制。按钮通过公开接口编排模型；App 继续自行解析 MQTT 并调用同一套基础接口。

“床尾 45% 视角”按床尾斜向 **45° 方位角**设计，镜头俯角另设约 32°，支持按型号调优。左右以站在床尾面向床头为准。

**1. 页面交互**

保留左侧模型舞台，右侧改为功能面板；型号选择收为紧凑选择器，将长状态列表改为各控制项附近的读数，详细状态可折叠查看。舞台底部保留视角按钮，增加“重置演示”。窄屏采用模型在上、控制在下，避免控件覆盖模型。

| 控制区 | 控件 | 行为 |
| --- | --- | --- |
| 自适应调节 | 左侧调节一次、右侧调节一次 | 每次遍历当前型号该侧所有控制部位，各调节一个周期后停止，不无限重播 |
| 运行状态 | 左右各自的部位、进度、停止按钮 | 两侧可同时运行；正在运行的开始按钮禁用，停止仅影响本侧 |
| 加热 | 左腰、左腿、右腰、右腿的关闭/低/中/高 | 按型号实际热区和最大档位生成，改变一个热区不影响其余热区 |
| 电动床 | 背部、腿部角度滑杆与数字输入 | 当前模板背部 0–65°、腿部 0–35°；显示当前展示角度与目标角度 |
| 姿态模式 | 平躺、阅读、零重力、舒展 | 设置预设角度；手动改角度后显示“自定义” |
| 运动速度 | 慢、标准、快及自定义 | 只影响床体折弯速度，运行中可改，不改变扫描、气囊、加热或镜头速度 |
| 镜头 | 立体、左后 45°、右后 45°、俯视、自动跟随 | 手动镜头不停止任何功能；自动跟随按钮明确显示是否开启 |
| 重置 | 重置演示 | 结束本页预览任务、恢复型号默认展示状态和初始视角 |

这里的左右独立指气囊和热区。现有电动床机构是整床背部/腿部两个角度，并非左右两套独立床架；本轮沿用该机构能力。

**2. 按钮数据与 App 数据**

本页新增按钮用于可操作的本地效果预览，状态明确标记“交互预览 · 本地数据”；不能继续显示“设备状态已同步”来描述按钮生成的数值。

- 预览编排放在单独控制器中，按钮不直接修改 Three.js 对象。控制器调用 setAirState、adjustment.begin/end、heating.setState、setPose 等公开接口。
- 模型核心不自行产生设备数据。App 嵌入入口默认仍使用外部数据，预览控制器不启动。
- 预览与 App 数据使用显式的来源模式，不允许两个来源同时向同一实例写入。切换为 App 模式时取消预览任务、使旧回调失效，清除预览数据并等待 App 初始状态；不更改设备绑定。
- 如果正式 App 后续也使用这套按钮 UI，按钮只发出交互意图给 App；App 使用已有控制逻辑处理，模型等待 App 回传状态。此次页面按钮不新增硬件命令、MQTT 连接或设备控制系统。

**3. 每侧一次完整编排**

单侧流程：

`请求床尾该侧 45° 镜头 → 本侧扫描进入 → 按顺序调节每个部位 → 本侧扫描退出 → 本侧完成`

默认 T11+ 顺序为肩背 → 腰部 → 臀部 → 腿部。顺序读取型号配置中的控制区域 ID，不按物理气囊下标循环；一部位对应两个气囊时，只执行一个控制任务，两个气囊共同响应。没有指定顺序时，按该侧控制部位的几何中心从床头到床尾排序。

建议预览节奏：

| 环节 | 默认参数 |
| --- | --- |
| 镜头转动 | 900 ms |
| 入场扫描 | 950 ms，从床头向床尾，仅本侧 |
| 每个部位 | 4 秒：从启动值到配置范围的 80% 位置 1.4 秒，保持 0.5 秒，降到 35% 位置 1.4 秒，再回到启动值 0.7 秒 |
| 退场扫描 | 950 ms，从床尾向床头恢复实体 |

默认四部位单侧约 19 秒，等待共享镜头的时间另计。80%/35% 是区域配置范围内的归一化展示值，不是压力、软硬度结论或设备自适应算法结果。预览初值来自型号预览配置，通用初值可设范围中点；不把该默认值写成真实设备读数。

实现要点：

- 进入时只把当前部位标记为工作，不把四个部位都伪装成同时工作。
- 部位交接采用一次原子 patch，包含“上一部位结束 + 下一部位开始”，同侧扫描状态保持；每侧每轮只入场一次、退场一次。
- 本页预览在扫描完成后开始播放数值曲线；App 的实际值随到随更新，镜头和扫描不得阻塞真实状态更新。
- 一轮完成回到该侧启动前的预览值。停止时冻结本侧当前展示值，结束本侧活动并扫描收尾；再次启动从该值继续。
- 每侧任务持有独立 taskId、取消标记和 modelToken，重复点击不叠加同侧任务。型号切换、重置、销毁后旧回调不再生效。

**4. 左右并行与视觉叠加**

现有状态存储已区分左右气囊、热区和角度，但 DevicePresentation 只有一个 side/phase/progress，显式扫描也只有一个 scanFlight。仅增加按钮仍会发生扫描相互覆盖，需要改为两侧各自独立的扫描状态与任务。

| 状态通道 | 独立管理的内容 | 允许覆盖的范围 |
| --- | --- | --- |
| 左侧气囊 | 当前部位、数值、任务、入场/退场进度 | 仅左侧任务 |
| 右侧气囊 | 当前部位、数值、任务、入场/退场进度 | 仅右侧任务 |
| 各加热区 | 档位、工作状态、热纹 | 仅相同热区 |
| 背部/腿部 | 当前角度、目标角度、运动速度 | 新目标替换同一轴的旧目标 |
| 镜头 | 当前视角、待转向侧、手动/跟随状态 | 只控制观察，不取消功能 |

表现规则：

- 只有左侧调节：左侧扫描后半透明，右侧保持实体；只有右侧调节则反过来。
- 双侧调节：左右分别保持自己的扫描阶段和半透明状态，可以同时看到两侧内部；一侧结束只恢复该侧外观。
- 这是对 V.18“仅焦点侧透视”的明确扩展。床垫仍保持整体，最透明处继续保留 38% 不透明度，不展开舒适层。
- 气囊维持左青绿、右冰蓝的科技光效，当前部位亮度最高；腰腿加热为表面橙金热纹。它们共同随床体折弯及气囊起伏，不把热区抬成独立悬浮层。
- 单独加热保持完整外观，不触发气囊扫描。气囊运行时开启/关闭加热不改变任一侧扫描状态。切换床体模式不清空气囊或热区。

CoverReveal 的扫描进度、开合和扫描光带参数需按侧存储；不能仅设 side='both'，因为两侧可能一侧入场、另一侧退场。内部气囊可见性与 FirmnessEffect 也需要逐侧使用对应状态。

**5. 共享镜头的确定规则**

一台镜头不能同时占据两个 45° 位置。因此两侧调节独立运行，镜头有自己的调度规则：

1. 单侧开始，转到该侧床尾斜向 45°，俯角约 32°；距离按型号、当前姿态和容器比例自适应，保留完整床体与主要气囊区域。
2. 另一侧随后开始，原侧继续运行，新侧申请镜头。已经开始的镜头入场及紧随其后的首次扫描先完成，再处理新的侧别请求，防止镜头未到位就连续反向。
3. 新侧镜头到位后播放自己的入场扫描，再开始本地预览曲线。前一侧不暂停、不重新入场、不恢复默认值。
4. 部位交接不重新申请镜头，避免左右四个部位交替抢镜头。双侧运行时保持最近一次明确启动/点选侧的视角。
5. 当前观察侧完成，另一侧仍在工作时，镜头可转回仍在运行的一侧；该侧已有扫描状态保持，不重新扫描。两侧同一帧开始时固定左侧先入场，右侧随后，结果可复现。
6. 用户拖动或点击固定视角后关闭自动跟随，所有调节继续；点击“自动跟随”恢复上述规则。手动镜头取消待转向请求，但不取消两侧任务；预览流程在镜头变为手动后直接完成本侧入场，不无限等待 camera.completed。
7. App 数据不等待镜头队列：两侧最新状态照常接收，摄像机只决定重点观察位置。新的自动焦点请求合并到各侧最新有效请求，不无限积压。

举例：左侧正在调腰部，点击右侧调节 → 镜头转右床尾，右侧扫描入场；左腰继续按自己的时间运行，随后进入左臀，右肩开始运行。此时开启左腰加热、切换阅读姿态，四种效果同时存在。停止右侧只收回右侧透视，其余功能继续。

**6. 加热与电动床**

加热区域和档位由 getModelInfo() 生成；默认四个热区独立，档位为 0–3。开启后持续显示，直到用户关闭或重置，不随自适应调节周期结束。预览不虚构温度和“已到温”结论。

电动床沿用现有姿态，作为当前模板的展示预设：

| 模式 | 背部角度 | 腿部角度 |
| --- | ---: | ---: |
| 平躺 | 0° | 0° |
| 阅读 | 52° | 10° |
| 零重力 | 28° | 24° |
| 舒展 | 14° | 32° |

这些角度来自现有 kinematics.js，不代表新增型号的实测硬件模式；后续型号可固化自己的预设和角度限制。

建议预览速度为慢 1.5°/s、标准 3°/s、快 6°/s，自定义暂定 0.5–10°/s。支持分别指定背部和腿部速度，页面默认使用一个速度设置同时应用两个轴。运动采用基于时间差的角速度限制，临近目标夹紧；不能用全局动画倍速影响其他效果。

- 从当前展示角度连续前进，抵达目标后停止，帧率变化不改变总角度速度。
- 运行中改速，从下一帧应用新速度，不回起点；修改单个轴，只替换该轴目标。模式按钮同时替换两轴目标。
- SDK 保留“跟随 App 实际角度”的默认策略；本页演示启用可调速过渡。切回 App 数据来源时恢复跟随策略，不强制套用慢速演示导致模型长期落后于上报。
- 速度只控制模型展示，不改变电机速度。观测值、预览目标和渲染插值在查询及 UI 中明确区分。

**7. 重置语义**

本页按钮命名为“重置演示”，保留当前型号，执行一次完整的复位：

1. 使左右任务、延迟回调和旧镜头请求失效，进入 resetting 状态，短暂禁用本页功能按钮。
2. 两侧扫描收尾，加热效果关闭；气囊恢复该型号预览初值，背部/腿部回 0°。
3. 返回完整外观，清除部位高亮和运行进度；恢复标准速度与默认缩放/目标点，停止自动旋转。
4. 床体复位采用独立约 1.2 秒过渡，之后按平躺包围范围恢复初始镜头，避免慢速设置让重置等待很久。最终恢复跟随待命，不主动启动任务。

无动态效果偏好时直接完成视觉复位。反复重置应幂等，不触发旧任务复活。运行中切换型号也要清理任务，但不先向旧型号写入“设备归零”。

App 数据模式下的 camera.reset() 仍只恢复视角，不清空真实状态；实际设备回平、关热由 App 自己执行并上报。预览重置不能借用“清空实际数据”来实现。

**8. 接口与文件改动**

以下是拟实现接口，不是 V.18 已有调用保证。保留现有分项状态接口，新增接口同步加入 JSON 分发白名单、状态查询和文档。

| 范围 | 拟提供调用 | 用途 |
| --- | --- | --- |
| 页面预览控制器 | preview.adjustment.runOnce('left'/'right')、stop(side) | 独立任务，按型号区域编排 |
| 页面预览控制器 | preview.heating.set(regionId, level) | 热区按钮调用现有 heating.setState |
| 页面预览控制器 | preview.bed.setAngles({back,leg})、setMode(id)、setSpeed(value) | 角度、预设和速度设置 |
| 页面预览控制器 | preview.reset() | 本地完整复位 |
| 模型 SDK | camera.focusSide(side, options?) | 精确床尾 45° 及自适应取景 |
| 模型 SDK | effects.scanOut({side, duration}) | 只退出指定侧；scanIn(side) 不取消另一侧 |
| 模型 SDK | motion.setPoseTransition({mode, backDegPerSec, legDegPerSec}) | follow 跟随 / rate 可调速，默认保持现有 App 语义 |
| 模型 SDK | getState().presentations.left/right | 查询每侧 phase/progress/activeRegionIds |

已有 getState().reveal 可保留为焦点侧的兼容摘要，新增字段给双侧调用者使用。旧版 scanOut() 无 side 时操作当前焦点侧，清空两侧必须明确调用两侧；完成和取消事件增加 side、taskId/actionId、modelToken，不把视觉完成当成设备完成。

| 文件 | 计划改动 |
| --- | --- |
| src/model-app.js、src/model-app.css | 新控件、来源标识、进度、响应式布局与桥接白名单 |
| 新增 src/preview-controller.js | 本地按钮编排、分侧取消、运行值恢复与重置；不包含 Three.js 操作 |
| src/device-state.js | 双侧呈现状态、原子部位交接；保留独立的设备值存储 |
| src/mattress-sdk.js | 镜头调度、每侧扫描、姿态过渡设置、事件和生命周期清理 |
| src/cover-reveal.js | 双侧独立扫描遮罩与材质恢复 |
| src/firmness-effect.js、src/model.js | 逐侧气囊可见性/高亮，保持整体结构及随动 |
| src/model-profiles.js | 可选区域顺序、预览初值、姿态预设和镜头参数，缺省兼容 V.18 |
| SDK/预览/遮罩回归与 docs/MODEL_SDK_API.md | 并行测试、更新实际接口和验收记录 |

不改原始参考图片、尺寸基线和静态 GLB 语义；旧设计工作台需要兼容检查。旧型号配置缺少新增可选字段时使用明确的通用默认值，T12 未配置时继续报错。

**9. 实施与验收**

实施顺序：先完成双侧呈现状态与取消机制，再接入按钮编排；随后实现姿态速度和共享镜头，最后完善布局并验证构建产物。

验收用例：

- 左、右各执行一次：每个控制部位恰好一次；每侧一次入场、一次退场；部位间不重新扫描。
- 错开启动左右任务：采样证明先启动侧的进度未重置/停顿；允许两侧不同扫描阶段，一侧退出不改变另一侧遮罩。
- 双侧调节 + 四区加热 + 阅读姿态：数值与视觉同时保持；仅加热不透视，折弯时光效贴合，无分层悬浮。
- 同侧重复点击不产生第二任务；停止一侧不停止另一侧、热区和床体运动；同轴重新定目标连续过渡。
- 1.5/3/6°/s 下验证角度到达时间，运行中改速不跳变，不改变其他动画时间；App 跟随策略不继承预览慢速。
- 镜头左右方位角对称且为 45°，双侧并发不反复抢镜头；手动接管不停止任务，也不使预览等待事件而卡住。
- 任意阶段重置、切型号、销毁：任务不会复活；晚到回调被拒绝；当前型号及资源隔离保持。App 模式重置视角不改设备状态。
- 不同区域数量、左右不对称、一部位多气囊、无加热型号均能生成正确控件和流程；不支持的能力不显示可操作按钮。
- 平躺、最大 65°/35°、两种床邦、四角贴合、深浅配色近景，以及 390 px 窄屏取景；减少动态效果、后台恢复、静止停绘和多次型号切换资源回收。
- 运行受影响回归、完整 npm test、npm run build，并在构建后的页面检查。以上为后续验收计划，当前未执行新功能验证。

交付为可直接操作的当前页面、独立预览控制器、扩展后的 SDK、接口文档及真实验证记录。桌面与模拟窄屏测试不替代原生 App、手机或真实设备联调。
