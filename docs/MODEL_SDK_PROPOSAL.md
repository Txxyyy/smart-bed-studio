# 多型号床垫模型与 App 动画接口方案

更新：2026-09-09。已按本方案实现 V.18 JavaScript 模型组件；实际接口以 [MODEL_SDK_API.md](MODEL_SDK_API.md) 为准。原生 App 桥接、真实设备联调和 T12 产品制作尚未完成。

## 1. 已确认范围

用户 App 和门店 App 都已有设备绑定、控制与 MQTT 处理。App 根据实际上报调用模型接口；模型不连接 MQTT，不下发硬件命令，也不需要 MQTT 报文样例才能对接。

模型承担两项主要职责：

- 设置型号后，加载该型号固化的外形、气囊布局、纹理、颜色、材质与型号标识。
- 提供气囊调节、加热、姿态、扫描和镜头接口，按 App 调用显示实际设备行为。

正式组件没有独立的模拟门店模式。现有固定时长循环保留在设计工作台用于视觉调试；App 展示中的调节数据由实际设备提供。

## 2. App 使用方式

```js
await mattress.setModel('T11+');
mattress.adjustment.begin(['left.lumbar']);
mattress.setAirState('left.lumbar', { value: 70 });
mattress.adjustment.end(['left.lumbar']);
mattress.heating.setState('right.leg', { level: 2, status: 'heating' });
```

App 可以调用这些分项接口，也可以通过 updateDeviceState 一次提交已解析的多个区域状态。这里使用模型公开的区域 ID 与参数，MQTT 字段解析由 App 自己完成；可选字段映射只是一项扩展能力，不是对接前提。

默认按活动侧自动转镜头、扫描进入，连续调用更新数值，最后一个活动区域结束时扫描恢复。App 也可显式调用 camera 和 effects 接口自行编排呈现。暂停或取消视觉效果不会操作设备。

## 3. 型号预设

| 配置内容 | 作用 |
| --- | --- |
| 型号身份、版本 | 让 App 选择确定的型号配置 |
| 几何模板、外观结构 | 床垫形态、腰线、包边及搭配 |
| 气囊实体与调节区 | 数量、位置、尺寸、所属侧、一个部位控制哪些气囊 |
| 加热区域 | 独立位置、尺寸和支持档位 |
| 颜色、材质、纹理、标识 | 固化该型号视觉细节 |
| 数值范围与视觉映射 | 将 App 传入的级别转换为形变与热纹强度 |
| 扫描、光效和镜头参数 | 控制该型号的表现方式 |
| 资源清单与配置版本 | 复现、验证和版本替换 |

气囊个数与可调节部位分开定义，一个部位可以关联多个气囊。热区不依赖气囊数组下标。数据与显示使用稳定的区域 ID，App 不引用内部网格顺序。

内置 T11+ 为现有参考配置，generic 为通用外观与明确的通用能力。T12 的真实资料尚未提供，目前返回 MODEL_NOT_CONFIGURED；登记完整 T12 配置后使用同一个 setModel 接口加载。通用外观可以复用，但不能用不明通道猜测另一型号的调节能力。

当前几何模板为 160 × 190 cm 的已有电动床垫；不同外轮廓或机构尺寸需要扩展模板后再固化，不能仅缩放已有机构冒充新规格。

## 4. 动画与状态原则

- 用户端和门店端采用相同模型接口，活动状态都由 App 通知。
- 扫描与镜头是视觉过程，不阻塞最新状态接收；同一次调节的连续更新不重复扫描。
- 同一侧多个区域可同时更新；左右同时运行时两侧数值都同步，App 可指定重点视角，只透视重点侧。
- 只有加热时保持完整床垫；气囊调节与加热并存时保持在同一床垫上的位置关系。
- 设备值、未知值与视觉插值分开；组件不把档位当作实测压力、温度或设备完成确认。
- 型号切换后清空旧状态和任务；加载标记用于拒绝异步晚到数据，不构成新的设备绑定系统。
- App 手动镜头、自动跟随及用户拖动具有明确的控制权切换。
- 暂停后继续接收值，恢复追随最新目标；静止和后台停止绘制。

## 5. 新型号制作流程

产品图片及必要规格 → 制作外形、材质、纹理与区域 → 用公开接口检查动画和镜头 → 用户查看并调优 → 确认 → 固化配置和资源 → 注册型号。

此流程不要求提供 MQTT 原始样例。内部气囊数量、位置和加热能力仍需产品规格支持，不能仅凭外观图片推断。已有模板可覆盖的型号主要新增配置和资源；超出模板的结构先实现相应几何能力。

## 6. 交付与验证

交付物为模型组件、纯画布嵌入页、型号预设、接口文档和验证记录。保留设计工作台用于材质与结构制作。

验证包括：无控件调用、动态气囊数量、一部位多气囊、连续调节、独立加热、镜头接管、显式扫描、型号切换、错误输入、晚到消息、后台停绘及资源清理；几何仍按项目要求检查最大折弯和两款床邦。

本轮真实验证记录见 VALIDATION.md；浏览器 API 测试使用明确的测试调用，不称为已接入真实设备。实际 App 的平台桥接及实机显示由后续联调验证。
